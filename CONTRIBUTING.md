# Contributing

Thanks for taking an interest in this small framework. A few ground rules first.

## Before you start

- The entire codebase was **generated by an AI coding assistant**. There is no
  human Unity/IL2CPP expert behind it. Treat every patch as unverified and
  please test it in an actual single-player battle.
- **Multiplayer is untested.** If you investigate multiplayer behaviour, report
  findings as an issue; do not assume the mod is safe or permitted online.
- This is a best-effort hobby project. Maintenance may be slow.

## What must NOT be committed

| Do not commit | Why |
| --- | --- |
| Any `.wav`, `.m4a`, `.mp3`, `.ogg` or other audio file | Copyrighted third-party material, not MIT-licensed. Users supply their own. See `NOTICE.md`. |
| Any game DLL, BepInEx DLL, Unity DLL or `interop/` assembly | Third-party binaries, generated per-machine, not redistributable. |
| `Directory.Build.props` | Contains your local absolute game path. Commit changes to `Directory.Build.props.example` instead. |
| `bin/`, `obj/`, `*.dll`, `*.pdb`, `*.deps.json` | Build output. Release binaries belong in GitHub Releases. |
| `*.log`, `*.bak`, editor/OS files, `.workbuddy/` | Personal data / noise. |

The root `.gitignore` already covers these. If you add a new kind of generated
file, please extend it in the same pull request.

## Reporting a bug

Please include:

1. Game version / store (Steam), Windows version, BepInEx version.
2. The plugin version or commit you built from.
3. **Single-player or multiplayer** (multiplayer reports are especially
   valuable, but note it is untested there).
4. What you did, what sound you expected, what actually played.
5. The relevant `[CKSF]` lines with `EnableDebugLog = true`, plus any warnings
   or errors from `BepInEx/LogOutput.log`.

See the *Debug logging* section of `README.md` for how to enable the log.
Please scrub your local absolute paths from pasted logs.

## Pull requests

- Keep changes focused and describe what you tested in-game.
- Do not reformat unrelated files; the codebase is generated and large diffs
  are hard to review.
- If you change a Harmony patch target, state which game method and which game
  version you verified it against — patches break silently after game updates.
- **Keep cfg comments minimal.** `Custom_Kill_Sound_Framework.cfg` should only
  say what each key does (plus its default). Naming rules, setup details and
  design rationale belong in `README.md` and the mod page. Because BepInEx
  rewrites the cfg from `ConfigDescription`, keep the descriptions in
  `ModConfig.cs` equally short — otherwise the file grows back on every rewrite.
- Keep cfg comments bilingual (Chinese / English) in both places.
- Keep the debug switch off by default and make sure disabled debug logging
  adds no cost on the per-frame / per-hit hot paths. Guard every diagnostic
  call with `if (Diag.Enabled)`.
- If you change the file-name grammar, update `SoundFileName.cs`,
  `SoundFileName` unit behaviour, `README.md`, `Sounds/README.md` and
  `build.bat`'s hint together. **Never add audio files.**
- The startup empty-folder check must stay a single English warning that is
  emitted even with debug logging off. Warnings and errors must never be routed
  through `Diag`.

## Building

See *Building from source* in `README.md`. In short:

```bat
copy Directory.Build.props.example Directory.Build.props
rem edit GameDir and InteropDir
build.bat
```
